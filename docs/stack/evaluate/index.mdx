## Use cases

These examples help you find the evaluation pages that match your scenario.
They are not a recommended deployment, and they are not features Lineth ships.

### Technical requirements

| If you need | Likely model | Read first |
| --- | --- | --- |
| Open access and onchain data availability | Public | [Deployment models](./deployment-models.mdx) |
| Transaction data kept off the finalization layer | Private validium | [Privacy and data visibility](./validium.mdx) |
| Multi-party workflows with scoped transaction visibility | Private validium | [Privacy and data visibility](./validium.mdx) |
| Protocol evidence for your own compliance program | Either model | [Compliance](./compliance.mdx) |

[Deployment models](./deployment-models.mdx) lists further examples for each
model.

### Example institutional scenarios

Operators often evaluate Lineth as the network for application workflows such
as the following.
Conditional settlement of two legs can be application logic on one network.
Do not infer a shipped cross-chain atomic interoperability product from these
examples.

| Scenario | What to evaluate | Read first |
| --- | --- | --- |
| 24/7 settlement | Always-on execution outside banking-hour rails | [Deployment models](./deployment-models.mdx) |
| Collateral mobility | Tokenized collateral pledged or reused with controlled visibility | [Privacy and data visibility](./validium.mdx) |
| Atomic Delivery versus Payment (DvP) | Two legs settle together, or neither does | [Privacy and data visibility](./validium.mdx), [Trust and responsibilities](./trust-model.mdx) |
| Intraday repo | Cash and collateral move together for a short window | [Privacy and data visibility](./validium.mdx), [Trust and responsibilities](./trust-model.mdx) |

## Evaluation criteria

### Deployment models

An <GlossaryTerm term="Operator">operator</GlossaryTerm> can deploy a public
network with onchain data availability, such as Linea Mainnet, or a private
<GlossaryTerm term="Validium">validium</GlossaryTerm> with offchain data
availability and controlled access.
Operators also choose access control, data availability, finalization layer,
finalization speed, and transaction ordering.

### Trust and responsibilities

Who operates each component, what that component can do unilaterally, and what
participants can verify depends on the deployment model.
Admin keys, upgrade authority, and failure modes are part of that evaluation.

### Privacy and data visibility

A deployment publishes state commitments and proofs to the
<GlossaryTerm term="Finalization layer">finalization layer</GlossaryTerm>.
Transaction data visibility depends on the data availability and access model.
Validium and role-based access control (RBAC) control where data lives and who
can read it; they are not cryptographic private execution.

### Security and assurance

Lineth provides state-transition correctness through
<GlossaryTerm term="zk-SNARK" /> proof verification on the finalization layer,
plus settlement finality scoped to that layer.
Operators own infrastructure security, keys, access control, and governance.
Published evidence includes the trusted setup, security audits, and Linea
Mainnet-specific records that do not certify a custom deployment.

### Compliance

A deployment produces state commitments, proof verification records,
finalization records, and transaction history retained by its data availability
model.
Operators own the compliance program.
Lineth does not certify a deployment or map controls to a regulatory framework.
